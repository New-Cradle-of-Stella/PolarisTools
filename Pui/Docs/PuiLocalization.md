# 在 .pui 里写本地化文本（`&` 前缀）

可视化编辑器里填的文字默认就是**写死的原文**——填"确定"，游戏里就显示"确定"，跟玩家用什么语言无关。

想让某个字段跟着语言走，**在最前面打一个 `&`**，后面写本地化键：

```
Text = &mymod.btn_ok
```

生成的代码就会变成 `XX.TX.Get("mymod.btn_ok")`，取值时去查你的 `.plang`。不用为了本地化把这个字段让出来、改到 `.pui.cs` 里手写。

## 哪些字段支持

| 控件 | 支持 `&` 的字段 |
|---|---|
| Text | `Text` |
| Button | `Text`（按钮上显示的标题） |
| ButtonMulti | `Titles`（`;` 分隔，**逐项**判断，可以键和原文混着写） |
| Checks / Radio | `Descs`（逐项） |
| Slider | `Text`（滑条标题） |
| ColorCell | `Text`（标题） |
| Input | `Label` |

**不支持**的字段，以及为什么：

| 字段 | 为什么不支持 |
|---|---|
| 所有控件的 `Name` | 是标识符，回调方法和状态连接点靠它匹配，翻译了就全断了 |
| Checks / Radio 的 `Keys` | 是回调里拿到的返回值，属于数据不是文案 |
| Slider 的 `DescKeys` | 同上，名字就叫 keys |
| Input 的 `Text`（初始值） | 是输入框里预填的**数据**，不是标签 |
| `Skin` / `ImageSource` | 资源名 |

简单记：**玩家会读到的那行字**支持，**代码要认的那个名字**不支持。

## 想显示一个真的 `&` 开头的文本怎么办

开头连打两个：`&&`，会脱掉一个变成字面量。

| 你填的 | 实际显示 |
|---|---|
| `&mymod.hello` | 查 `mymod.hello` 的译文 |
| `&&nbsp;正文` | `&nbsp;正文`（原样，不查表） |
| `正文&nbsp;更多` | `正文&nbsp;更多`（原样） |
| `&` | `&`（只有一个 `&`，空键没意义，当字面量） |

**判定只看第一个字符**，字符串中间的 `&` 永远原样保留。所以开了 `Html` 的 Text 控件里写 `A&nbsp;B` 是安全的，只有 `&nbsp;A` 这种**开头就是 HTML 实体**的才需要写成 `&&nbsp;A`。

> 上表说的都是你在**编辑器属性面板里填什么**。`.pui` 是 XML，存盘时 `&` 会被自动写成 `&amp;`（`Text="&amp;mymod.hello"`），这是 XML 自己的转义，编辑器帮你处理，不用管。只有直接用记事本改 `.pui` 时才需要自己写 `&amp;`。

## 键写错了会怎样

`TX.Get` 查不到你的键时，会退回游戏原版的文案表去找，最后显示什么由游戏决定。`&` 语法本身走的还是 `XX.TX.Get`（被 `Patch_TX_Get` 拦下来问一遍 `PolarisAPI.Localization` 的 resolver 链），而 `.plang` 生成的 `Lang.某个键` 属性是直接调 `Polaris.Lang.PlangRuntime.Get` 拿同一份文案，省了中间那层 Harmony patch——两条路径最终查到的文案完全一致，只是多一跳。

编辑器画布上会**原样显示 `&mymod.hello`**（而不是空白），就是为了让你一眼看出这个键没查到。

## 编辑器预览

画布会去扫**当前项目里的 `.plang` 文件**，查到就直接画出译文，查不到就画 `&键名`。改完 `.plang` 保存，画布会自动刷新，不用重开编辑器。

两点要知道：

- 预览显示的是 `.plang` 文件里写的原文，一个键只在一份 `.plang` 里定义。
- Checks / Radio 的预览格子画的是 `Keys`，不是会被本地化的 `Descs`——所以这两个控件在画布上看不出本地化效果，这是预览一直以来的画法，不代表没生效。

真正的取值永远走 `XX.TX.Get`，会问 resolver 链、会跟着游戏当前语言走，这些编辑器模拟不了。预览只是让你设计时不用对着一串键名猜排版。

## 换语言之后什么时候生效

**切完就生效，不用重开游戏、也不用自己动手。**

原理值得知道一下，因为这里有个不那么直觉的地方：`TX.Get` 的调用点在生成代码的 `BuildUI` 里，而
`BuildUI` **只在窗口第一次构建时跑一次**——`PUIRuntime` 第一次 `Show` 才 `Build()`，之后的
Show/Hide 只是 `activate()`/`deactivate()` 同一个已经建好的窗口。所以光靠"关掉重开"是刷不掉旧文案的。

Polaris 每帧比对游戏当前的本地化 family（`PolarisAPI.Game.LocaleChanged`），变了就把
**已经构建过的 PUI 全部重新取词**：正在显示的立刻重建并保持显示（焦点也一起恢复），
隐藏着的先拆掉、下次显示时自然重建。

一个副作用要留意：重建等于把窗口重新走一遍 `BuildUI`，所以**窗口里的运行时状态会回到初始值**
（输入框里填过的字、勾选状态等）。切语言这种低频操作下这么做是划算的——游戏自身的界面同样是重建的。

## 热重载也一样

编辑器点热重载推过去的窗口，和编译出来的窗口走的是同一套 `&` 规则（共用同一份判定代码），文案不会出现两边对不上的情况。
